# Pane Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add Windows 11 style tabs independently to each QuadPane panel.

**Architecture:** `PaneView` owns a list of tab states, each with a persistent `ExplorerHost` in the visual tree. A custom Avalonia tab strip selects and closes tabs. `LayoutData` saves paths and selected indices, while `MainWindow` routes keyboard shortcuts to the active panel.

**Tech Stack:** .NET 10, Avalonia 12, Windows `IExplorerBrowser`.

**Spec:** `docs/superpowers/specs/2026-11-04-pane-tabs-design.md`

## Global Constraints

- Keep existing user changes and current 1–4 panel layouts, search, theme, and shortcuts.
- Each tab keeps its own live Explorer Browser during the session.
- Persist tab paths, stable view identifiers, and selection with backward compatibility for existing single paths.

## Review Focus

- Switching tabs after navigating back and forward preserves each tab's history.
- Closing a selected tab activates a neighbor; closing the final tab keeps the panel usable.
- Native input in a tab still activates the owning panel and routes shell accelerators.
- Reopening old layout JSON yields one tab in each panel.
- Narrow panels leave the add button and active tab reachable.
